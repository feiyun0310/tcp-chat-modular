# 验证与测试

执行 `bash build.sh`，然后 `PYTHON=/usr/bin/python3 bash test.sh`。
编译器开启 `-Wall -Wextra -Wpedantic`。CI 的实际结果见仓库 Actions；
没有本地 Linux 工具链时不能把源码检查描述为编译通过。

| 层次 | 检查内容 |
|---|---|
| Queue 单元测试 | 容量拒绝、FIFO、Stop 后排空、唤醒等待者 |
| Frame 单元测试 | 逐字节半包、连续帧、二进制内容、超长长度 |
| ChatService 单元测试 | 昵称冲突、频道隔离、存储失败、登录回滚、历史格式错误、退出、断线 |
| 集成：基础聊天 | 真实登录、重复昵称、中文消息、频道广播、历史读取、退出后拒绝发消息 |
| 集成：顺序 | 一条 TCP 流中混合分片登录帧和 30 个连续消息，核对历史顺序 |
| 集成：历史 | 写 105 条消息，精确检查剩下最后 100 条 |
| 集成：生命周期 | 断开连接后昵称可再次使用 |
| 集成：协议异常 | 超长帧关闭；错误 JSON 和错误字段类型不会杀死数据服务器 |
| 集成：客户端 | 运行真实客户端，输入消息和 /quit，验证消息已保存且没有退出超时 |
| 集成：故障与关闭 | 数据服务器停止后登录返回错误，服务可受控退出 |

集成测试启动单独的临时 Redis（禁用持久化）、动态端口及两个服务器进程。
正常或异常结束时回收子进程；测试不使用 FLUSHDB/FLUSHALL。
Python Protobuf 代码由与 C++ 同一份 proto 生成。Ubuntu apt 安装的 Python 包
使用 `/usr/bin/python3`，避免与另外安装的 Python 环境混用。

可选检测：`SANITIZERS=address,undefined bash build.sh` 后再运行 `test.sh`。
只有真正执行并通过的 CI 才能作为证据；该可选命令本身不表示已经做过 sanitizer 测试。

尚未覆盖压力测试、跨主机网络故障、磁盘持久化故障、全部慢连接/恶意流量组合和分布式部署。
这些不应被 README 的功能列表误解为已验证能力。
